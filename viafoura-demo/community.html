Viafoura Community Tools

Implementation Guide
November 11, 2026 Additional Components

Beyond the main engagement products, Viafoura ships a set of smaller components that help readers find, share and follow conversations. This page implements each one from the Additional Components docs, with a live widget, the code behind it and its options.

Every widget below sits in its own <div class="viafoura"> wrapper and is loaded by the same SDK script as the rest of the site:

<script async src="https://cdn.viafoura.net/entry/index.js"></script>

Comment Count

Shows just the number of comments on a conversation. Use it on article cards, home pages and section fronts to point readers toward active discussions. The widget only renders the number, so any icon or label around it is up to you.

Live demo · a listing page
Implementing Viafoura Conversations comments Artificial Intelligence and Its Impact on Modern Society comments The Global Transition to Sustainable Energy comments The Future of Work in a Digital Age comments

On an article page, leave out the attribute and the count reads the page's vf:container_id meta tag:

<div class="viafoura">
  <vf-conversations-count></vf-conversations-count>
</div>

On a listing page like the one above, every count needs its own vf-container-id, or they would all show the listing page's count:

<div class="viafoura">
  <vf-conversations-count vf-container-id="P1001"></vf-conversations-count>
</div>
Attribute Default Description
vf-container-id Page meta tag Which conversation to count. Required when a page shows counts for several articles.

For pages with many cards, Viafoura recommends the Bulk Comment Count API, which fetches every count in one request instead of one widget each.

Trending Conversations

A list of the articles with the most comment activity, for recirculation in a sidebar or at the end of a story. It ranks pages by visible comments posted within the trend window, then by total comments, and refreshes about every five minutes. The current page is always left out. It comes in two layouts: a vertical list (vf-trending-articles, with a full and a condensed view) and a horizontal carousel (vf-content-recirculation), which also has an ad position.

It stays empty until other pages have comments. Post on Conversations or the SPA articles and it will fill in. Pages with no visible comments are never listed.

    sort="comments"
    view="full">

<!-- Carousel: same attributes, no view -->
<div class="viafoura">
  <vf-content-recirculation
    title="Trending Conversations"
    limit="5"
    days-published="30"
    trend-window="48"
    sort="comments">
  </vf-content-recirculation>
</div>
Attribute Default Description
title Trending Articles Heading at the top of the widget
limit 5 Number of articles, 1–100
days-published 7 Maximum article age in days, 1–30 (all also works on the vertical list)
trend-window 3 Hours of comment activity to rank by, 1–48
sort comments Currently the only option
view full full or condensed (vertical list only)
vf-container-id Page meta tag The current page, so it's excluded from the list

Images: each article's thumbnail comes from its og:image (or vf:image) meta tag. Use a 3:2 image, ideally 210×140. That's why every page on this site keeps an og:image tag even though the pages show no images.

This demo uses the widest windows (30 days, 48 hours) so a low-traffic test site still has something to show. If fewer than limit stories qualify, Viafoura widens the windows to those maximums anyway.

Carousel ad. Once Viafoura switches ads on for Trending, the carousel fires requestContentRecirculationAd for a 300×250 slot. This page fills it with the site's shared Google Ad Manager handler; the setup is under Ads in Conversations.

Social Share Bar

Share buttons with live share counts. The networks shown, and their order, are set in Viafoura Admin rather than in the markup. The markup controls the look: icon shape, layout, labels and counters.

Live demo · circle icons with counters and total
Square icons · black and white · borders
Single share button (data-button-view="true")
<div class="viafoura">
  <div class="vf-widget vf-share-bar-circle"
       data-widget="sharebar"
       data-show-counters="true"
       data-show-total="true"
       data-button-view="false">
  </div>
</div>
Attribute Default Description
data-widget — Must be sharebar
data-show-total true Total share count at the end of the bar, updated live
data-show-counters true A count on each network's button, updated live
data-show-labels false Network names next to the icons (vertical bars only)
data-button-view false One share button that opens the bar as a dropdown, or full screen on touch devices
data-path / data-url Current page The page to share. Use one or the other, not both.
data-share-current-page-url false Share whatever URL is in the address bar. In a single-page app, call window.vf.context.reset() when the URL changes.

Style classes go on the vf-widget element:

  • Icon shape, pick one: vf-share-bar-default, vf-share-bar-circle or vf-share-bar-square
  • vf-share-bar-vertical stacks the buttons vertically
  • vf-share-bar-borders adds a border; vf-share-bar-bw makes it black and white
  • With data-button-view="true", use vf-share-button-default, -circle or -square
  • Add inline-block to the viafoura wrapper to sit the bar inline with other content

On screens narrower than 765px, a horizontal bar shows the first three networks and a "show more" button.

Heads up: the docs say this version of the Share Bar will be deprecated in favour of a WCAG 2.2 AA–compliant version, so check the docs before recommending it to a client.

Share Count

The page's total share count on its own, without the buttons. It reads the same counts as the Share Bar, so set the bar up first. If the bar uses data-path or data-url, the count must use the same value.

shares 
<div class="viafoura">
  <div class="vf-widget vf-quote"
       data-widget="sharetotal"
       data-realtime="true">
  </div>
</div>
Attribute Default Description
data-path Current page Path of the page to count, e.g. /viafoura-demo/community.html
data-url — Full URL of the page to count
data-realtime true false loads the count once and doesn't update it live

Share a page with the bar above and watch this number change. The VF Events panel (bottom left) also logs sharebar and share-total events.

Custom Follows

Follow buttons for a topic or an author. Readers manage what they follow in the Community tab of the notification tray, and get a tray notification when the publisher announces new content for that topic.

Live demo · plain button (topic) and with follower count (author)
Viafoura Implementation Guides Topic
Beau Lazear Author 
<div class="viafoura">
  <vf-topic-follow
    topic-id="authorbeaulazear"
    topic-name="Beau Lazear"
    topic-type="Author"
    show-count="true"
    minimum-count="0">
  </vf-topic-follow>
</div>
Attribute Default Description
topic-id — (required) Internal ID for the topic. Not shown to readers; avoid special characters.
topic-name — (required) Name readers see in the Community tab after following
topic-type topic Any label, such as Author. Shown to readers.
show-count false Show the follower count on the button
minimum-count 0 Hide the count until it reaches this number

The button has two views: the plain Follow button (the default, as on the topic above) and the button with a follower count (show-count="true", as on the author). With minimum-count, the count stays hidden until enough people follow, so a new topic doesn't show "0 followers".

Sending the notifications. Following only subscribes the reader. To notify them, the publisher calls the Broadcast Notifications API with a title, description, image and URL, usually from the CMS when an article is published. Viafoura has no screen for sending broadcasts. To avoid duplicate notifications, give each article a single topic.

Not the same as following a conversation. The Follow button at the top of the comments subscribes a reader to new comments on that one article. A topic follow subscribes them to new articles.

Notification Bell

The bell opens the notification tray, where readers log in, see replies and manage what they follow. A badge on its corner counts unseen notifications and clears when the tray opens. It has two views: inline, placed in the page like any element (in a site header, for example), and floating, pinned to the bottom-right of the screen. A page can have any number of bells, and if there are none, the Conversations widget adds one to itself.

  <vf-tray-trigger floating="true"></vf-tray-trigger>
</div>

Standalone Ad

An ad unit on its own, for a spot on the page with no other Viafoura product. It uses the same settings and layout as the trending carousel, takes no attributes, and fires requestStandaloneAd for a 300×250 slot, which this page fills through Google Ad Manager. Viafoura support has to switch it on for the site first; until then the space stays empty.

Editor's Pick & Trusted User

These have no markup of their own. They're set by a moderator or admin, and show up inside the Conversations widget:

  • Featured comment (Editor's Pick): a moderator marks a standout comment as featured. It gets a Featured Comment badge and appears in the Featured tab, which shows top-level comments only, not replies.
  • Trusted user: gets an icon beside their name, and their comments skip moderation and spam filters.

Try it: post a comment in the conversation at the bottom of this page, feature it as a moderator, then reload. It should appear in the Featured tab with its badge.

Badges

Badges label users in comments. There are four kinds, and only one is set from the page.

Author badge (page markup). Tell Viafoura who wrote the article with a meta tag, and that person's comments on it get an Author badge. The value is the author's Viafoura user ID, or a third-party ID with a prefix such as oidc: or cookie::

<meta property="vf:owner" content="viafoura-id:YOUR_USER_ID" />
  • Use vf:owner or vf:author, never both.
  • For several authors, add one tag per author.

This page doesn't set one yet, because it needs a real user ID from the site. Add your account's ID and your comments here will show the badge.

Trusted, Moderator and Custom badges (API). No page markup. With a client ID and secret from Viafoura:

  1. Get a JWT from the Authorize Client API (it lasts 5 minutes).
  2. Create a badge type with a label (internal) and description (shown to readers).
  3. Assign it to one user per request, by user_uuid or third-party ID.

Badges can also be assigned automatically from webhooks, for example after a reader's 100th comment. Viafoura has to switch webhooks on first.
