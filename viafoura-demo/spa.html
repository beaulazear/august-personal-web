Load Different Articles

Each article has its own container ID (P3001–P3003). Switch articles and the comments below reload for that article without a page refresh. The VF Events panel logs each reset.

How this differs from a regular implementation

The widget markup is the same as on any other page: one <vf-conversations>, with the container ID in the vf:container_id meta tag. The difference is when Viafoura reads it. Viafoura reads the page's meta tags once, when the SDK starts. On a normal site every article is a full page load, so that happens on its own. In a single-page app the page never reloads, so after each navigation we have to update the tags ourselves and tell Viafoura to start again.

Regular page This SPA
Meta tags Written once in the HTML Rewritten with JavaScript on every navigation
Loading a new article The browser loads a new page and Viafoura starts fresh We call vf.context.reset()
Page views and attention time Sent automatically on each page load Sent by reset(): attention time for the old article, a page view for the new one
Direct links Each URL is its own page ?article= sets the tags before the SDK loads, so no reset is needed

Each navigation runs three steps, in this order:

// 1. Load the new page: content and URL
history.pushState({}, '', '?article=article-2');

// 2. Point the meta tags at the new article
document.querySelector('meta[name="vf:container_id"]').content = 'P3002';
document.querySelector('meta[property="og:url"]').content = location.href;
document.querySelector('meta[property="og:title"]').content = 'New title';

// 3. Rebuild the widgets from the new tags
window.vfQ.push(function () {
  window.vf.context.reset();
});

The order matters: if reset() runs before the tags change, the widgets reload the old conversation. See Viafoura's Single Page App Setup docs.
