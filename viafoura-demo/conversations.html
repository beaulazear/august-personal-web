Implementing Viafoura Conversations

Implementation Guide
November 4, 2026 Technical Documentation

What is Viafoura Conversations?

Viafoura Conversations is a real-time commenting platform designed to enable deep audience engagement with your content and community members. It emphasizes civil discourse through industry-leading moderation tools while maintaining your publisher brand integrity.

Start with the Engagement Starter

Most readers never scroll far enough to find the comments. The Engagement Starter fixes that: it's a small prompt you place partway through the article that invites readers into the conversation and, when clicked, takes them straight down to it. Because it's built to point at the comments, it only works on a page that also has the Conversations widget, so it's the natural first piece of a Conversations install.

The prompt adapts to the conversation on its own:

  • It follows the comment count. "Be the first to comment" on a new article, "Read the comments" with one to five, and "Read the [count] comments" above that. On a closed conversation it reads "Read the comments", or hides entirely if there are none.
  • It can show a highlighted comment. When a moderator pins or features a comment, that comment replaces the default text. A pinned comment wins over a featured one, only the most recent is shown, and replies can't be featured.
  • It can run a poll. Moderators and admins see a Create Poll button on the starter. Questions are up to 120 characters, with 2–10 options of up to 100 characters each, and an optional close date. Without one, the poll runs until it is closed by hand.
  • It can carry an ad. A 300×250 ad unit can run next to the starter, from the publisher's own ad server or Viafoura's inventory. This page fills it through Google Ad Manager; see Ads in Conversations below.

How it's wired up. The starter's target is the id of the <div class="viafoura"> wrapping the Conversations widget, written without a #. That id must be unique on the page.

<!-- In the article -->
<div class="viafoura">
  <vf-conversation-starter
    target="conversations-widget"
    title="Have your say."
    description="Leave a comment below and let us know what you think."
    minimum-comment-count="5">
  </vf-conversation-starter>
</div>

<!-- Further down: the Conversations widget, with the matching id -->
<div class="viafoura" id="conversations-widget">
  <vf-conversations></vf-conversations>
</div>
Attribute Default Description
target — (required) The id of the Conversations widget's wrapper
title Have your say. Heading of the prompt
description Leave a comment below and let us know what you think. Text under the heading
minimum-comment-count 5 Comments needed before the count is shown
vf-container-id Page meta tag Only needed if the page uses widget-level container IDs

Try it: as a moderator, pin or feature a comment in the conversation below and the starter will show it, or create a poll from the starter itself.

With the starter in place, the rest of this guide covers the Conversations widget it leads to.

Key Features

  • Real-time comment loading - Comments appear instantly as users post them
  • Multi-tab interface - Standard and featured comments views
  • Flexible sorting - Newest, oldest, most-liked, most-replied
  • Reply threading - Nested conversations with customizable depth
  • Active Conversations - Shows trending stories based on recent comment activity
  • Performance optimized - Height management and CLS reduction built-in

Basic Implementation

The simplest way to add Conversations to your page requires just two steps:

Step 1: Load the Viafoura SDK

<script async src="https://cdn.viafoura.net/entry/index.js"></script>

Step 2: Add the widget

<div class="viafoura">
  <vf-conversations></vf-conversations>
</div>

Container ID Setup

Each page needs a unique container ID to keep comments separate. You can set this in two ways:

Option 1: Meta tag (recommended)

<meta name="vf:container_id" content="P1001">

Option 2: Widget attribute

<vf-conversations vf-container-id="P1001"></vf-conversations>

Configuration Parameters

Customize the widget behavior with these parameters:

Parameter Default Description
limit 10 Initial comments loaded (1-100)
pagination-limit 10 Comments per page load (1-100)
reply-limit 2 Initial replies per comment (0-100)
sort newest Comment ordering (newest, oldest, most-liked, most-replied)
initial-height null Fixed height in pixels (600px recommended for CLS reduction)

Example with parameters:

<vf-conversations
  limit="20"
  reply-limit="5"
  sort="most-liked"
  initial-height="600">
</vf-conversations>

Layout Customization

The customization panel below demonstrates two layout options:

  • Default (unchecked) - Comments appear below the article content
  • Collapsible Side Tray (checked) - Comments slide in from the right, similar to notifications

Both layouts use the same widget code - only the CSS positioning changes. This demonstrates Viafoura's flexibility in adapting to different publisher designs.

Performance Best Practices

  • Set initial-height="600" to reduce Cumulative Layout Shift (CLS)
  • Use article-level container IDs via meta tags for cleaner code
  • Enable trending articles in admin to drive recirculation
  • For high-traffic pages, consider limit-live-experience parameter

Required: Notification Tray

Conversations relies on the notification tray for login, replies, and follow actions. Make sure to include:

<vf-tray-trigger floating="true"></vf-tray-trigger>

Ads in Conversations

Conversations and the Engagement Starter both have built-in ad positions: between comments, inside reply threads, in the footer of the comment list, and beside the starter. Viafoura doesn't serve these ads itself. When a position is ready, the widget fires an event with the id of an empty element, and the publisher's code puts an ad there. That means any ad server works, and the publisher keeps the revenue. This page runs both, so scroll the comments below and you'll see ads appear between them.

Step 1: Load Google Publisher Tag. disableInitialLoad() stops GPT fetching anything until a widget asks for an ad.

<script async src="https://securepubads.g.doubleclick.net/tag/js/gpt.js"></script>
<script>
  window.googletag = window.googletag || { cmd: [] };
  googletag.cmd.push(function () {
    googletag.pubads().enableSingleRequest();
    googletag.pubads().disableInitialLoad();
    googletag.enableServices();
  });
</script>

Step 2: Write a handler. It receives the slot's element id, defines a GPT slot on it and fetches the ad:

function generateAd(slotName) {
  googletag.cmd.push(function () {
    // Clear any old slot that used the same element
    var stale = googletag.pubads().getSlots()
      .filter(function (s) { return s.getSlotElementId() === slotName; });
    googletag.destroySlots(stale);

    var slot = googletag.defineSlot('/1234/your/ad-unit', [300, 250], slotName)
      .addService(googletag.pubads());
    googletag.display(slotName);
    googletag.pubads().refresh([slot]);
  });
}

Step 3: Subscribe to the Viafoura events.

window.vfQ = window.vfQ || [];
window.vfQ.push(function () {
  window.vf.$subscribe('vf-ads', 'requestCommentAd', generateAd);
  window.vf.$subscribe('vf-ads', 'requestConversationStarter', generateAd);
});
Event Product Ad size
requestCommentAd Conversations (comments, replies, footer) Any; use a size mapping per device
requestConversationStarter Engagement Starter 300×250
requestLiveblogAd Live Blog Same as Conversations
requestContentRecirculationAd Trending Conversations 300×250
requestStandaloneAd Standalone Ad widget 300×250

This site's version of the script is assets/ads.js, shared by every page with an ad position. It uses Google's public sample ad unit, which serves test creatives, and logs each request and render to the VF Events panel. A real install swaps in the publisher's own network code and ad unit path.

Switching ads on. The markup isn't enough. Viafoura support turns ads on for each widget (Conversations, Engagement Starter, Live Blog, Trending, Standalone) and sets the provider:

  • Google Tag: the widget shows a slot only after Google Ad Manager reports an ad rendered in it, so empty slots stay hidden.
  • Custom: for any other ad server. The slot is shown as soon as it's requested, filled or not.

How often ads appear. In the Advertising page of Viafoura Admin:

  • First promo position, Promo interval, Promo interval for replies. Where the first ad goes and how many comments sit between ads. Viafoura recommends 1-6-6.
  • Threshold. How far ahead of the viewport a slot starts loading. The default is 90px.

Ads in replies. Viafoura has to switch these on. To stop ads stacking up, the reply interval adjusts itself:

  • If the parent comment, or the comment after it, already has an ad, the reply interval doubles for that thread.
  • If the last reply lands on an interval, it only gets an ad when another comment follows.
  • If the last comment in the list has an ad, the footer ad is skipped.

Turning ads off on one page. Add <meta property="vf:ads-disabled"> at page load (it can't be changed afterwards, even by a context reset), and hide the positions with .vf3-conversations-list__promo { display: none; }.

If ads look cropped, look for a global iframe { max-width: 100%; } rule, often from a CSS reset, and scope it to your own iframes instead.
