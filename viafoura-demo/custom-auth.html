Understanding Custom Authentication with Viafoura

By Technical Documentation Team
November 4, 2026 Technical Guide

Many publishers have existing user authentication systems and want to integrate Viafoura seamlessly with their current login infrastructure. Viafoura's custom authentication allows you to maintain your existing user database and authentication flow while still leveraging Viafoura's engagement features.

How Custom Authentication Works

The integration follows a simple pattern:

  1. Listen for authentication events: When a user tries to interact with Viafoura widgets (commenting, liking, etc.), Viafoura fires an authentication/needed event.
  2. Show your login UI: Your code intercepts this event and displays your authentication interface (modal, redirect, OAuth popup, etc.).
  3. Authenticate the user: Process the login through your existing system.
  4. Pass user data to Viafoura: After successful authentication, call vf.session.login() with the user's information.
  5. Viafoura takes over: The widgets update to show the logged-in state and enable authenticated interactions.

Required User Data

When calling vf.session.login(), you need to provide:

  • user_id: Unique identifier from your system
  • name: Display name for the user
  • email: User's email address
  • user_token: JWT token signed with your Viafoura secret key

The user token is critical for security—it proves to Viafoura that your backend has verified this user's identity.

Benefits of Custom Authentication

  • Single sign-on: Users only need to log in once across your entire site
  • Unified user database: Keep all user data in your existing system
  • Existing security policies: Maintain your current authentication, password policies, and security measures
  • Seamless experience: Users don't need to create separate Viafoura accounts

Production Implementation

In a production environment, you would:

  1. Replace the mock login dialog below with your actual authentication UI
  2. Have your backend generate a proper JWT user token after authentication
  3. Pass the token securely to the frontend (never expose your secret key client-side)
  4. Handle token refresh for long-lived sessions
  5. Synchronize logout across your site and Viafoura
